# Concepts

* [Publishing events through a transactional outbox](concepts/transactional-outbox.md) - Write the state change and an outbox row in one transaction, then let a single relay claim rows, publish them under the row id, and mark them done — so what was published can never diverge from what was committed.
* [Dispatching through one relay and a broker](concepts/relay-to-broker-dispatch.md) - Let exactly one relay publish into a durable broker and give every consumer its own durable subscription there, so consumers keep their position in the broker rather than in the source database — and know the threshold at which database notifications stop being enough.
* [Making delivery safe with end-to-end idempotency keys](concepts/end-to-end-idempotency.md) - Assume at-least-once at every hop and give each retry boundary a stable key generated by whoever retries — a client key at capture, a unique constraint at ingestion, the same identity as the broker message id, and consumers idempotent on it.
